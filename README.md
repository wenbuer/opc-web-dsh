# OPC 智能体工作台（opc-web）

> 一人公司（OPC）的日常指挥台：**浏览器打开 → 下达任务 → 各 AI 角色按职责产出 → R0 批阅、归档入库**。
> 所有指令都由常驻主会话 R1 拆解派发执行；控制台只负责「下达与记录」，不亲自跑 agent。

## 它是什么

一个纯本地的 Web 控制台（Python 标准库实现，**零第三方依赖**），围绕一套「AI 角色体系」运转：

- **一份角色体系**：R0 创始人（拍板、批阅）→ R1 老板助理（枢纽，调度派发）→ R2~R9 自带业务角色（需求研究、内容工厂、增长运营、用户洞察、数据分析、财务合规、产品设计、技术评估…），还可按需新增。
- **三个工作目录**（首次启动自动生成）：
  - `批阅台/` —— 公文与台账：批阅台、决策日志、调度日志（md，人读人写）+ `opc.db`（任务/子任务/回报台账，SQLite）
  - `工作区/<角色名称>/` —— 每个角色的产出（如 `工作区/内容工厂/T-001-S1.md` 与同名 `.meta.json`），归档后移入 `已归档/`
  - `知识库/` —— 档案与索引（角色架构、知识库索引），只读，由 R1 维护
- **一套执行模型**：你在控制台下达任务 → 任务落台账并生成「调度指令」→ 常驻主会话 R1 读到指令，把任务拆成子任务、用 subagent 逐个派发给对应角色 → 角色把产出写进自己工作区的子任务文件 → R0 批阅 → 归档入库。
- **一条存储分界**：状态（任务/子任务/回报）在 SQLite，正文与公文（回报正文、批阅台、决策日志、知识库）仍是 md。md 不再当数据库用。

> 一句话：**控制台下达，R1 拆解，角色执行，R0 把关。**

## 快速开始

1. **启动**：双击 `启动控制台.bat`（自动开浏览器），或命令行 `python run.py`。
2. **打开**：浏览器访问 `http://127.0.0.1:8901`（端口可在配置里改，见「目录设置」）。
3. **可选**：在「设置 → 模型接入」填入大模型 API Key，否则 R1/角色没有可用的模型后端。
4. 首次启动会自动生成 `批阅台/ 工作区/ 知识库/` 三个目录与骨架文件，无需手动创建。

准备好后，去「作战面板」下达第一个任务试试。

## 视图怎么看、怎么用

### 1. 作战面板（首页）—— 下达任务、看组织

- **组织架构**：顶部 R0（创始人）、R1（枢纽）常驻；下方是 R2+ 角色卡片，点击任意卡片 → 右侧显示该角色工作区与角色卡全文。
  - 卡片右上角 **✎ 编辑角色**：弹窗修改名称/定位/类型/职责，保存后角色卡同步更新。
  - 卡片右下角 **🗑 删除角色**：弹窗二次确认后才删除（移除角色卡、工作区、架构登记；R0/R1 受保护不可删）。
  - 底部 **＋ 新增角色**：弹窗新建（自动编号 R10+），立即生成角色卡与工作区。
- **任务下达**：输入任务（如 `R3 以内容工厂身份写一段产品介绍文案`）→ 提交 → 任务落台账（T-编号），同时生成调度指令待 R1 执行。
- **R1 调度区**：显示调度状态（台账有待派 → 已生成指令 → 待主会话执行）；拆解结果直接落台账，无需再手工「落地产出」。
- **agent 执行监听**：可切换「直跑观测」（控制台本地直接跑任务）或「主会话实时」（监听 DSH 主会话 R1/subagent 执行事件）。

### 2. 批阅台 —— R0 把关

- 查看待批阅内容、回报、调度日志、子任务台账；
- **R0 批阅**：对角色回报做出批阅写入（决策进入《决策日志》、归档进入《归档登记》）；
- R1 归档按钮把角色产出落库到知识库。

### 3. 工作台 —— 全程跟踪

- 左侧任务行（T-xxx）→ 右侧「任务详情」：子任务、执行角色、回报、产物与调度日志聚合展示；
- 运行监控：直跑观测的实时执行日志。

### 4. 知识库 —— 档案阅读

- 知识库根直接平铺展示档案；出现子目录时自动分组（如 `知识库/档案/`）；
- 点击任一档案查看全文；档案由 R1 维护，角色只读。

### 5. 每日简报

- 阅读《批阅台/每日简报-*.md》，每天一份，R1 汇总产出。

### 6. 设置 —— 目录、模型、定时任务

- **① 目录设置**：只需填一个**根目录**（默认项目根；保存后自动生成 批阅台/工作区/知识库，工作区按角色名称建子文件夹）；端口在 opc-config.json 的 `port`。
- **② 模型接入**：提供方（deepseek/openai/anthropic/custom）+ API Key + baseURL + 模型，可「测试连通」真实请求 1 token 校验。
- **③ 定时任务**：每天/每周/每隔 N 分钟三种模式，填任务指令，到点自动写入任务队列并生成调度指令由 R1 执行；支持启停/删除。

> 角色新增与编辑已整合进作战面板（＋新增 / ✎编辑弹窗），设置页不再单独提供。

## 一条完整任务怎么走（示例）

`R3 以内容工厂身份把本周产品动态整理进《知识库索引》`

1. 作战面板「下达任务」提交 → 任务落台账 T-001；
2. 执行链拆解为子任务 T-001-S1…，落台账并预置 `工作区/内容工厂/T-001-S1.md` 与 `T-001-S1.meta.json`，同时把【派发指令】写入《调度日志》；
3. 常驻主会话 R1 读取指令 → 逐个 subagent 派发；
4. R3 边做边把进度追加进 `T-001-S1.md`，完成后把 `T-001-S1.meta.json` 的 `status` 改为 完成/部分/阻塞；
5. 点「🗂 归档」→ 控制台把已完成子任务的正文入库、文件移入 `已归档/`，子任务全完成时任务自动置「完成」；
6. 批阅台查看回报 → R0 批阅 → 决策入《决策日志》；工作台任务详情可回看全程。

## 定时任务怎么配

设置 → ③ 定时任务：

- **模式**：每天（固定时刻）/ 每周（星期几 + 时刻）/ 每隔 N 分钟；
- **内容**：填写任务指令（就是你想让 R1 按时执行的内容，写法同下达任务）；
- 到点后控制器自动把任务落台账并生成调度指令 → 走与手动下达完全相同的 R1 执行链路；
- 列表可随时**停用/启用/删除**，下次触发时间实时显示。

## 模型接入怎么配（一次搞定，全体系受益）

设置 → ② 模型接入：

1. 选提供方（deepseek / openai / anthropic / custom）；
2. 填 API Key —— **只写入项目根 `.env`**，不落配置明文、不回显、不入库；
3. baseURL / 模型按需覆盖（留空用提供方默认）；
4. 点「测试连通」确认密钥有效。

接入后，dsh 会话与所有角色 subagent 自动继承同一凭据（惯例同 dsh 模型 API：提供方 → `<ROUTE>_API_KEY` 环境变量）。

## 配置与数据（知道这些够用）

**配置优先级：环境变量 > `opc-config.json` > 默认值。** 两个配置文件都不入库。

### `opc-config.json` 字段

| 字段 | 默认 | 设置页可改 | 生效 | 说明 |
|---|---|---|---|---|
| `root` | 项目根 | ✅ | 保存即生效 | 总根目录，其下自动建 批阅台/工作区/知识库 |
| `port` | `8901` | ✅ | **需重启** | 监听端口（socket 已绑定，改后必须重启） |
| `model` | — | ✅ | 保存即生效 | `{provider, apiKeyEnv?, baseURL?, model?}`；**密钥不写这里** |
| `schedule` | `[]` | ✅ | 保存即生效 | 定时任务列表，见「定时任务怎么配」 |
| `pollSeconds` | `8` | ❌ 手改 | 即时 | 调度守护轮询间隔（秒） |
| `decomposeTimeout` | `480` | ❌ 手改 | 即时 | 拆解任务时 headless 的无输出超时（秒），模型慢就调大 |
| `maxSubtasks` | `2` | ❌ 手改 | 即时 | 单个任务最多拆成几个并行子任务 |

> 后三项是调优旋钮，刻意不进设置页 UI；手改 `opc-config.json` 即时生效，无需重启。
> 设置页保存不会覆盖你手改的字段（写入走「读盘 → 合并 → 写盘」）。

### 环境变量

| 变量 | 覆盖 |
|---|---|
| `OPC_CONFIG` | 配置文件路径（默认项目根 `opc-config.json`） |
| `OPC_KB_ROOT` | 根目录（优先于 `root`） |
| `OPC_PORT` | 端口（优先于 `port`） |

### 数据落地

| 项 | 说明 |
|---|---|
| 凭据 | 只写项目根 `.env` 的 `<PROVIDER>_API_KEY`；不进 `opc-config.json`、不回显 |
| 状态台账 | `批阅台/opc.db`（SQLite，标准库 `sqlite3`）：任务/子任务/回报三张表，唯一真相；仅控制台进程写入 |
| 运行数据 | 批阅台/工作区/知识库 由启动时自动生成/幂等重建，**不入库**，仓库保持干净 |
| 角色定义 | `agents/R?.role.md` 随项目分发；派发时由 `agent_prompt()` 把角色卡全文注入子 agent 的 prompt |
| 监听地址 | 固定 `127.0.0.1`（仅本机可访问，无配置开关） |

## 隐私与提交规范

上传 GitHub 前，以下内容默认**不提交**（已在 `.gitignore`）：

- `.env` —— 大模型 API 密钥（**绝对不要提交**）；
- `opc-config.json` —— 本机运行配置（root/port）；
- `批阅台/ 工作区/ 知识库/` —— 运行数据与业务内容。

提交前检查 `git status`：只应出现源码（src/、templates/、static/、agents/、tests/、run.py、pyproject.toml、README.md 等）。
